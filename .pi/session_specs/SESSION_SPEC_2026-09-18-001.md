# Nozzle 1: Skill routing

Execute directly as the implementing agent. Do NOT delegate to heavy_think.
Binding contract: VERIFYING.md (all sections). House style: erasable TS, node:test, zero runtime deps.

## Frozen design (evidence-backed, do not re-litigate)

- Catalog: scan Pi skill locations (`~/.pi/agent/skills/`, project `.pi/skills/`, `~/.agents/skills/`,
  `.agents/skills/`), directories containing `SKILL.md`. Built-in skill discovery is assumed
  disabled by the owner (`enableSkillCommands`/settings); the extension owns routing.
- Digest: newest-first walk of session entries, user turns + assistant text/thinking only,
  tool calls and results excluded. Budget 80KB (~20k tokens). Pure input preparation, not judgment.
- Scoring: at `before_agent_start`, one Jev request per NOT-yet-active skill, fully parallel.
  State = digest. Question = Noul with the FULL skill body embedded in instructions.
  Endpoint POST https://api.typesafe.ai/v1/systemone, model `jev-latest` (config), Bearer key
  from config-named env var or file. Never log the key.
- Policy: load threshold 0.6, top-K cap K=3 by score. Both in config with these defaults.
- Injection: via `context` event, fixed position (immediately after system prompt), byte-stable
  within an epoch. Active set frozen until `agent_settled`.
- Lifecycle: skip-active (never re-score loaded skills); decay re-check every 5th user turn at
  0.25; `/skill:name`-style manual loads are pinned (never decayed).
- Telemetry: append-only JSONL log, `ROUTE_DECISION: epoch=… scores={…} loaded=[…] skipped_active=[…] evicted=[…] latency_ms=… input_tokens=…`.
  `/skill_stats` command renders aggregates (loads, evictions, hit distribution, tokens spent).

## Milestones

- M1 spike: extension loads, registers on `context`, injects one hardcoded skill body into the
  message copy, byte-stable across two consecutive events. Proves the seam before any Jev wiring.
  Test: fake `context` event objects, assert injection position + byte-stability.
- M2 router: catalog scan, digest builder (unit tests: newest-first ordering, tool-content exclusion,
  80KB cap), Jev client behind one injectable function (tests use a fixture server, NEVER network),
  threshold+top-K policy, frozen-set injection.
- M3 lifecycle: skip-active, decay re-check, pinned manual loads, telemetry JSONL + /skill_stats.

## Acceptance

`npm run check && npm test` green; every VERIFYING.md §5 Nozzle-1 scenario mirrored as a passing
node:test; no `any`; zero runtime deps; Jev client fully mockable without edits.

## Learnings

- M1 (2026-09-18): seam proven. `ContextEvent.messages` is the deep-copied list; injecting one
  synthetic `UserMessage` at index 0 places it immediately after the system prompt. The frozen
  object is cached per epoch and cleared on `agent_settled`, so byte-stability holds by object
  reuse. Pi 0.85.1 does NOT export `ContextEventResult` from the package root — the module
  declares `SkillInjectionResult` (structurally identical) instead. `AgentMessage` includes
  `BashExecutionMessage` (no `content`), so consumers must role-narrow to `UserMessage` before
  reading content. Types come from devDeps `@earendil-works/pi-{coding-agent,agent-core,ai}`
  0.85.1 via `import type` only — erased at runtime, zero runtime deps intact.
- M2 (2026-09-18): router core landed. Config = defaults <- user JSON <- project JSON
  (`~/.pi/agent/jev-context.json`, `<cwd>/.pi/jev-context.json`); key from config-named env var
  or file. Catalog mirrors Pi discovery (SKILL.md dir = skill root, no recursion below, first
  root wins name ties). Digest walks newest-first (cap drops oldest) but emits chronologically —
  per-message parts must be offered in reverse or the final flip inverts them (caught by test).
  `SessionEntry[]` from `getBranch()` is structurally assignable to the local `DigestEntry`.
  Regression pinned: `onBeforeAgentStart` must not rebuild the router (lazy-init guard);
  unguarded init wiped the active set every turn and double-notified in absent mode.
  `response.json()` failure maps to `bad_response`, distinct from network `unreachable`.
